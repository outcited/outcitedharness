## Exact dependencies / what M4 must provide for LIVE integration

1. **Service availability**: `POST /v1/engineering/decisions` on :8793 (or
   an agreed address). Not reachable at implementation time — M5 client is
   implemented (`HttpTransport`) and failure-tested, but has never made a
   live call. Live parity is PENDING, per PRD §14.
2. **Contract version disclosure**: the live response must carry
   `schema: harness.electronics-decision-answer.v1` (or a successor the
   client is told to expect). M5 rejects mismatches as structured
   `contract_mismatch` — no silent acceptance.
3. **Request shape M5 sends** (validated against the frozen contract):
   `{question: {requirements:{vin_min,vin_max,vout,iout_min},
   conditions:{vin_v,vout_v}, operating_point:{x,unit},
   phenomenon:"efficiency_vs_load"}}` — canonical SI floats. If CURVE-08B
   changed the envelope, M4 publishes the OpenAPI and M5 adapts the client
   (one module, `m4_client.py`).
4. **Release identities in responses**: `evidence_release` +
   `bundle_sha256` (already present in the frozen answers — keep them).
   M5 stamps every session with them and fails structured on
   `expected_releases` mismatch.
5. **Identity stability**: M4 candidate ids (`cand-<hash>` over
   manufacturer/category/family/device/grain) must stay stable across
   bundle regenerations for the same candidate, or ship a crosswalk delta.
   The M5 crosswalk is regenerated by
   `scripts/discovery01_freeze_m4_journeys.py` (deterministic; fixture sha
   pins it per release).
6. **Auth/network policy** before any cross-machine serving: M5 is
   localhost-only; if M4's :8793 stays on another host, agree transport
   auth (M5 keeps credentials out of browser-visible responses and logs).

## What M5 will NOT do (ownership guarantees)

- No eligibility recomputation, no curve interpolation, no comparison-level
  logic — M4's answers pass through unmodified (orchestrator renders; tests
  assert values equal fixture values).
- No promotion of advisory curves to gold; review states render as-is
  (`verification_pending` suggestions preserved).
- No merging of M4 branches; consumption is via the pinned fixtures above.

1. **Mount migration (cosmetic, not data).** The NAS mirror (`nas://m5-4tb`)
   is now reached under a different volume letter than on 2026-10-18
   because the local `local://M5_4TB` volume is detached in this run. All
   `vault_cas`, `staging_root`, `cr_core`, `nas_gold`, `nas_validated`
   counts are unchanged across the two mounts; `producer_at` for each is
   unchanged. Directory `size_bytes` differ only because directory inode
   size is filesystem-specific (NAS vs local) — not a content signal.
2. **`gold_mount_dead` flipped.**
   - 2026-10-18: `available=False` (UNKNOWN) — "dead since 2026-10-16".
   - 2026-10-28: `available=True`, `producer_at=2026-10-14T16:11:41Z`.
   This is a source-availability difference (the path now stats), not a
   funnel data change. It is recorded, never summed.
3. **`export_root` (SERVED release) is a DIFFERENT export snapshot.**
   This is the only difference with any bearing on served data:

   | field | 2026-10-18 | 2026-10-28 |

   On 2026-10-18 the export contained a `parts_a_pinout.jsonl` (378 rows)
   and a newer cube.json. On 2026-10-28 that file is absent from the export
   dir and cube.json is the 2026-10-14 export (also pinned by

   The current export does contain `compare_ready.jsonl` (27,458 rows),

   Interpretation: the served release was **re-folded / reverted** to an
